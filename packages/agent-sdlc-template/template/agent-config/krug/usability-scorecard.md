# Usability Scorecard

A rubric for evaluating the usability health of a page, flow, screen, app, or site against the principles in *Don't Make Me Think*. Score each criterion 0-10. Total is out of 100.

| Criterion | 0-10 | Notes |
| :--- | :--- | :--- |
| **Self-evidence** | | Can a stranger answer "what is it / how do I use it" without thinking? Failing that, is it self-explanatory? |
| **Scanning support** | | Visual hierarchy, conventions, defined areas, generous headings, short paragraphs, bulleted lists, key terms highlighted. |
| **Mindless choices** | | Each click/tap is an unambiguous "obviously the right thing." When unavoidable, guidance is brief, timely, and unavoidable. |
| **Word economy** | | Half of the words removed, then half again. No happy talk, no needless instructions, no mission statements masquerading as copy. |
| **Navigation clarity** | | Persistent nav with Site ID, Sections, Utilities, Search, Home link. "You are here" indicator. Page name prominent and matching what was clicked. Passes the trunk test. |
| **First-impression / "big picture"** | | Within seconds the user can answer: What is this? What can I do here? What do they have here? Why should I be here (not somewhere else)? |
| **Conventions vs. innovation** | | Uses standard patterns where they exist; only deviates when a clearly better idea earns the learning curve. Clarity beats consistency. |
| **Goodwill reservoir** | | Behaves like a mensch — surfaces what users want, saves steps, candid about costs/limits, recovers gracefully from errors, apologises when warranted. |
| **Mobile fitness** | | Allows zoom or uses responsive design; deep links go to the linked content (not the mobile home page); affordances survive flat design; performance is fast on slow connections. |
| **Accessibility floor** | | Fixes the usability problems that confuse everyone first; appropriate alt text, semantic headings, labelled forms, "Skip to Main Content," keyboard-operable, sufficient contrast, accessible template. |

**Total Score:** ___ / 100

## How to use this scorecard

- Score one surface at a time. Don't average a whole product into a single number — the issues live at the page or flow level.
- Pair the score with a debrief that lists the *three most serious* problems observed (see `usability-testing-doctrine.md`). Severity-ranked findings matter more than the headline number.
- Re-score after each round of fixes. The score is a tracking instrument, not a verdict.
- Have at least one person who didn't build the thing fill it in. The team's score and an outsider's score diverging is itself a finding.

## Severity bands

- **80-100:** Strong. Most users will move through smoothly. Focus on polish and edge cases.
- **60-79:** Decent. A handful of fixable issues are costing real users real time.
- **40-59:** Weak. Users are muddling through but goodwill is being drained.
- **0-39:** Broken. Stop arguing about colour schemes and run a usability test.
