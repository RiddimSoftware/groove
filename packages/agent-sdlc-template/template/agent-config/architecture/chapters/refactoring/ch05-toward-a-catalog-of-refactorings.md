# Chapter 5: Toward a Catalog of Refactorings

## Summary
This brief chapter introduces the format used for the rest of the book—the catalog of specific refactorings.

## Format of a Refactoring
Each refactoring in the catalog follows a standard structure:
1. **Name:** Important for building a vocabulary among developers.
2. **Summary:** A short explanation of the refactoring and why you would do it, often accompanied by a simple "before" and "after" code sketch.
3. **Motivation:** An explanation of the "why." When should this refactoring be used? What smells does it fix? When should it *not* be used?
4. **Mechanics:** A concise, step-by-step guide on how to perform the refactoring safely. This is the recipe.
5. **Examples:** Detailed code examples walking through the mechanics in practice.

## Finding Refactorings
The catalog is organized into broad categories (Composing Methods, Moving Features, Organizing Data, etc.). The "Bad Smells" chapter (Chapter 3) acts as a cross-reference, pointing you from the problem to the recommended refactorings in the catalog.
