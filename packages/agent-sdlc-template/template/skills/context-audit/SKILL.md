# context-audit

Audit and remediate Riddim repository agent-context drift.

This skill has three responsibilities:

1. Select repositories: one repo, all repos, or repos changed since a ref.
2. Run deterministic checks D1-D9 by invoking the AGENT-51 library in `agent-config`.
3. Add the grounded judgment pass J1-J4, then open at most the configured number of remediation PRs.

Do not reimplement D1-D9 in this skill. The deterministic source of truth is
`/YOUR/WORKSPACE/DIR/agent-config/scripts/context_audit/`.

## Inputs

Supported selection modes:

- One repo: `--repo <name-or-path>`
- All repos: `--all`
- Changed since: `--changed-since <ref>`; combine with `--all` or `--repo` when useful

Operational flags:

- `--max-prs <n>` caps PRs opened in one run; default is `5`.
- `--no-pr` is dry-run mode. It prints the plan and judgment findings, edits nothing, pushes nothing, and opens zero PRs.

Planner command:

```bash
python context-audit/scripts/audit.py --repo autopilot --no-pr --include-clean
python context-audit/scripts/audit.py --all --max-prs 5 --no-pr
python context-audit/scripts/audit.py --all --changed-since origin/main --no-pr
python context-audit/scripts/audit.py --repo /YOUR/WORKSPACE/DIR/autopilot --format json --include-clean
```

The planner is intentionally side-effect-free. It selects repos, invokes the
AGENT-51 D-check library, applies dedup/cap planning for deterministic drift,
and renders evidence for PR bodies. The agent running this skill performs the
J1-J4 review, edits files, and emits PRs.

## Required Workflow

### 1. Confirm prerequisites

- Ensure `/YOUR/WORKSPACE/DIR/agent-config/scripts/context_audit/` exists.
- Ensure `/YOUR/WORKSPACE/DIR/agent-config/context/repositories.yaml` exists.
- Ensure the `agent-config` checkout used for evaluation is current enough to contain the merged AGENT-51 JSON contract. If the root checkout is stale or dirty, create a clean verification worktree at `origin/main` and pass it with `--agent-config <path>` or set `CONTEXT_AUDIT_AGENT_CONFIG=<path>`.
- If this run is tied to a Linear issue, re-check the issue state first and continue only when it is active.
- Use a dedicated worktree for every repository you edit. Never switch a root checkout off `main`.

If the AGENT-51 library is missing, stop. Do not fork or rewrite the deterministic checks here.

### 2. Build the deterministic plan

Run the planner in dry-run mode first, even for an executing run:

```bash
python context-audit/scripts/audit.py --all --max-prs 5 --no-pr --format json --include-clean
```

Use the requested selection mode. Keep the JSON output as the run ledger:

- `clean` means D1-D9 produced no failures or warnings.
- `remediate` means D1-D9 produced failures or warnings and no existing audit PR was found.
- `deduped` means an open audit PR already exists; update it or skip it, but never open a second PR.
- `deferred` means over the per-run cap; leave it for a future run.
- `error` or `no_checkout` is a run blocker for that repo, not a reason to guess.

Warnings count as deterministic drift. A fully compliant fleet has zero fail, zero warn, and zero judgment findings.

### 3. Run the J1-J4 judgment pass

For every selected repo that is not deferred over the cap, read only the files needed to judge the context:

- `CLAUDE.md`
- `AGENTS.md` if present
- the mapped directories named in `## Repository Map`
- nearby docs or generated-file headers only when a context claim points at them

Evaluate:

- `J1 Map still accurate` - map purpose lines still match the dirs.
- `J2 Prose still true` - stated invariants/landmines are still true; new recent invariants are captured.
- `J3 Missing landmines` - generated files, irreversible migrations, release-vs-integration semantics, or other real foot-guns are named.
- `J4 Right altitude` - always-loaded context is concise; deep details are pointers to docs, while load-bearing rules are inline.

Ground every judgment finding in repo evidence. No evidence means no finding.

Use this finding format:

```markdown
- **J3:** Added generated-file landmine for `AGENTS.md` because its header says it is generated by `scripts/sync-org-agent-instructions.sh`.
```

If J1-J4 find no issues, write `No judgment findings.` in the PR body or dry-run output.

### 4. Decide whether to open PRs

Combine deterministic findings and judgment findings per repo.

- If a repo has no deterministic findings and no judgment findings, no-op for that repo.
- If the entire selected set is clean, exit successfully after printing `opening 0 PRs`.
- Respect `--max-prs` after combining D and J findings.
- If an open `context-audit` PR already exists for a repo, update that branch or skip; do not open a duplicate.
- If a fix requires edits in more than one repository, skip that repo and report the split needed. One audit finding may produce one PR to one repository, never a multi-repo PR.

Most fixes are made in the audited repo. Registry-only fixes for `repositories.yaml`
belong in `YourGithubOrg/agent-config`; do not mix those with target-repo context
file edits in the same PR.

### 5. Apply fixes in a worktree

For each repo selected for remediation:

1. Fetch latest main in the root checkout:
   ```bash
   git fetch origin main
   ```
2. Create or reuse a dedicated audit branch. Use the stable branch name `context-audit/drift` for that target repo so repeated runs dedup naturally.
3. Create a worktree off latest `origin/main`; if the branch already exists, work in that branch and rebase it onto `origin/main`.
4. Apply the narrowest fix that addresses the cited evidence.
5. Rerun the deterministic library for that repo:
   ```bash
   cd /YOUR/WORKSPACE/DIR/agent-config
   python -m scripts.context_audit <repo-path> --format json
   ```
6. Re-run the J1-J4 reasoning against the changed context file and update the PR body evidence.

Deterministic repair guidance:

- `D1`: add `CLAUDE.md`. For a stub repo, start from `/YOUR/WORKSPACE/DIR/agent-config/context/templates/minimum-repo-CLAUDE.md`, replace placeholders with concrete registry/local evidence, and avoid unfilled `TODO`/`TBD`/`Unknown`/`FIXME` markers.
- `D2`: replace placeholders with concrete context or `N/A - <reason>` when a field genuinely does not apply.
- `D3`: replace a duplicate or oversized `AGENTS.md` with the thin shim that points to `CLAUDE.md`.
- `D4`: move deep details into `docs/` and leave a pointer, unless the detail is a load-bearing invariant.
- `D5`: add or repair the `## Project Snapshot` block in the standard schema.
- `D6`: update stale map paths or tag genuinely planned dirs as `(planned)`.
- `D7`: fix stale commands or use explicit `N/A` when a command does not exist.
- `D8`/`D9`: decide from evidence whether the repo context file or the registry is wrong; keep the PR single-repo.

### 6. Emit the PR

Commit only the context-audit fix:

```bash
git add -A
git status --porcelain
git commit -m "context-audit: refresh <repo-name> agent context"
git rebase origin/main
git push -u origin context-audit/drift
```

Create the PR with developer-bot identity:

```bash
gh pr create \
  --title "context-audit: refresh <repo-name> agent context" \
  --body-file -
```

If the PR already exists, update the branch and body instead of creating another:

```bash
gh pr edit <url-or-number> --body-file -
```

Arm auto-merge for every audit PR:

```bash
gh pr merge --auto --squash <url-or-number>
```

The PR body must include:

- Selection mode and run date.
- Deterministic findings with AGENT-51 messages.
- Judgment findings with evidence.
- What changed.
- Verification commands and results.
- Any skipped findings and why.

### 7. Cleanup and stop conditions

Clean up only worktrees created by this run after their branches are pushed.

Stop successfully when:

- no selected repo has drift, or
- the PR cap is reached after opening/updating capped PRs, or
- all selected drift has been remediated.

Stop blocked when:

- the AGENT-51 library is unavailable,
- GitHub auth would open PRs as a human user,
- a required checkout is missing and cannot be resolved from the registry,
- the required fix spans multiple repositories,
- or verification cannot run for a reason that invalidates the PR.
